About the Project

Comprehensive project report detailing system architecture, academic subjects applied, engineering methodology, and project boundaries.

Project Overview

The Bank Transaction Anomaly Flagger is an intelligent, multi-layered financial transaction screening system engineered as a B.Tech computer science capstone project.

Modern banking ecosystems handle millions of transactions every second. While the vast majority are legitimate, fraudulent actors frequently attempt illicit transfers, account takeovers, and money laundering. Rather than relying on a single detection technique, this project brings together discrete logic, graph theory, object-oriented software engineering, and statistical anomaly mathematics to flag unusual transactions for human compliance review.

Problem Statement

Traditional rule-based screening systems often suffer from high false positive rates and struggle to detect subtle patterns such as sudden deviation from a customer's spending history or multi-hop money routing through newly created beneficiary accounts.

Conversely, pure black-box machine learning approaches often lack explainability, making it difficult for bank compliance auditors to understand why a transaction was flagged. There is a critical need for an explainable, multi-tiered screening solution that combines deterministic rule validation, structural relationship mapping, and statistical variance scoring.

Project Objectives

  • Early-Stage Anomaly Detection: Identify suspicious transactions before funds are settled or cleared.
  • Multi-Factor Verification: Combine deterministic propositional logic with historical statistical baselines.
  • Graph-Based Topology Analysis: Analyze account-to-payee relationships to detect unfamiliar nodes and circular transfers.
  • Transparent Audit Trails: Provide clear, explainable decision factors for every flagged transaction.
  • Zero External Storage Overhead: Maintain a lightweight, modular computational architecture.

How the System Works

1
Input Ingestion:

Transaction attributes (Account, Amount, Payee, Location, History) are structured into memory objects.

2
Propositional Rule Validation:

The system evaluates truth conditions against safety rules (e.g. Amount > Threshold ∧ NewPayee = True).

3
Statistical Outlier Calculation:

Calculates the customer's mean ($\mu$) and standard deviation ($\sigma$). If $Z = \frac{X - \mu}{\sigma} > 2.5$, it triggers an anomaly score.

4
Relational Graph Inspection:

Maps source and destination accounts to check connection frequency and unverified hops.

5
Decision Output:

Combines scores into a final deterministic label: NORMAL or FLAGGED FOR REVIEW.

Academic Subjects Applied

This project directly integrates five core computer science curriculum subjects into a unified engineering solution:

DMGT

Discrete Mathematics & Graph Theory

Utilizes propositional logic formulas, truth tables, and conditional implications to build deterministic decision trees for rule evaluations.

AI

Artificial Intelligence

Implements heuristic risk-scoring, multi-criteria decision models, and adaptive thresholding for triage automation.

ADSA

Advanced Data Structures & Algorithms

Applies graph data structures (adjacency lists, directed graphs, cycle detection) to inspect fund flows between accounts and identify money-mule clusters.

OOPJ / Java

Object-Oriented Programming (Java)

Implements structured domain modeling with encapsulation, abstraction, and polymorphism to handle transaction lifecycle and rule evaluation chains.

Python

Python Statistical Core

Powers numerical analysis, calculating mean, variance, and Z-score metrics to detect statistical outliers in user transaction histories.

Project Scope

  • First-Pass Screening: Serves as an immediate pre-clearance filter before banking settlements.
  • Academic Demonstration: Designed to validate discrete logic, graph structures, and statistical variance in financial security.
  • Explainable Decisions: Every flagged output highlights the exact rule, graph node, or statistical score that was violated.
  • Zero Database Footprint: In-memory and statistical computation suitable for lightweight college presentations.
